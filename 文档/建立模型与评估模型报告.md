# 建立模型与评估模型

本文档详细介绍了AP/IB达标率预测模型的建立过程与评估结果。整个建模流程分为两个主要阶段：模型建立和模型评估。

---

## 一、建立模型

建立模型阶段包括问题定义、特征工程、模型选择与配置，以及数据划分与训练策略的制定。

### 1.1 问题定义与目标变量构建

在开始建模之前，我们首先需要明确预测目标。基于前期的探索性分析，我们发现AP和IB的评分标准存在差异：AP考试中，3分及以上（level 3-5）被视为达标；而IB考试中，4分及以上（level 4-7）才被视为达标。因此，我们需要根据`APIB_IND`字段来分别计算不同项目的达标人数。

具体来说，对于AP项目，我们将level 3、level 4和level 5的学生人数相加得到`pass_cnt`；对于IB项目，则将level 4、level 5、level 6和level 7的学生人数相加。然后，通过`pass_cnt`除以`tested_student_cnt`得到达标率`proficient_rate`。

考虑到这是一个二分类问题，我们设定阈值为0.5：当`proficient_rate >= 0.5`时，标记为达标（标签为1）；否则标记为不达标（标签为0）。这个阈值的选择基于教育实践中的常见标准，即当超过一半的学生达到合格水平时，可以认为该学校在该科目上表现良好。

在数据清洗过程中，我们过滤掉了以下情况：
- `proficient_rate`为NaN的记录（通常是因为`tested_student_cnt`为0或缺失）
- `tested_student_cnt < 10`的记录（样本量过小，统计意义有限）
- `proficient_rate`不在[0, 1]范围内的异常值

经过这些处理，最终得到了可用于建模的数据集。从结果来看，达标样本和不达标样本的比例相对均衡，这为模型训练提供了良好的基础。

### 1.2 特征选择与预处理

在特征选择方面，我们综合考虑了数值特征和分类特征。数值特征包括：
- `aggregation_index`：聚合索引
- `NRC_CODE`：资源需求代码
- `COUNTY_CODE`：县代码
- `NYC_IND`：是否位于纽约市
- `tested_student_cnt`：参加考试的学生人数

分类特征包括：
- `aggregation_type`：聚合类型
- `LEA_NAME`：学区名称
- `NRC_DESC`：资源需求描述
- `COUNTY_NAME`：县名称
- `SUBGROUP_NAME`：学生子群名称（如经济困难、种族、性别等）
- `APIB_IND`：AP或IB项目标识
- `SUBJECT_AREA`：学科领域
- `GRADE_LEVEL`：年级水平

对于缺失值处理，我们采用了不同的策略：数值特征在数据加载阶段已经通过`pd.to_numeric`进行了转换，缺失值被标记为NaN；分类特征则统一填充为"UNKNOWN"，以避免信息丢失。

在特征预处理方面，我们构建了一个`ColumnTransformer`，对数值特征使用`StandardScaler`进行标准化，对分类特征使用`OneHotEncoder`进行独热编码。这里遇到的一个小问题是sklearn版本兼容性：新版本（>=1.2）使用`sparse_output`参数，而旧版本使用`sparse`参数。我们通过try-except来处理这个问题，确保代码在不同环境下都能正常运行。

### 1.3 模型选择与配置

考虑到这是一个二分类问题，我们选择了多种不同类型的分类算法进行对比，包括：

**线性模型**：
- Logistic Regression：经典的线性分类器，作为baseline
- Lasso（L1正则化的Logistic Regression）：用于特征选择

**基于距离的模型**：
- KNN Classifier：k=5，适合处理非线性关系

**支持向量机**：
- SVM Classifier Linear：线性核
- SVM Classifier RBF：径向基函数核，能够捕捉复杂的非线性模式

**树模型**：
- Decision Tree：max_depth=20，防止过拟合
- Random Forest Classifier：n_estimators=100，max_depth=20
- RandomForest（来自train.py）：n_estimators=300，更深的树和更多的样本要求

**梯度提升模型**：
- XGBoost Classifier：n_estimators=100，使用GPU加速（如果可用）
- XGBoost（来自train.py）：n_estimators=500，更复杂的配置
- LGBM Classifier：n_estimators=100，同样支持GPU加速

**神经网络**：
- MLP Classifier：隐藏层结构为(100, 50)，使用early stopping防止过拟合

**概率模型**：
- Naive Bayes：假设特征之间相互独立

在模型配置方面，我们特别关注了计算效率。对于XGBoost和LightGBM，我们尝试使用GPU加速（CUDA 13），如果GPU不可用则自动回退到CPU。这在实际运行中确实提高了训练速度，特别是对于大规模数据集。

对于SVM模型，我们设置了`max_iter=1000`和`tol=0.001`，并增加了`cache_size`，以避免训练时间过长。即便如此，SVM模型在训练过程中仍然遇到了收敛问题，这在最终结果中也有所体现。

### 1.4 数据划分与训练策略

我们采用80/20的比例划分训练集和测试集，并使用`stratify=y`确保训练集和测试集中达标样本的比例保持一致。随机种子设置为42，以保证结果的可重复性。

所有模型都封装在sklearn的`Pipeline`中，这样可以确保预处理步骤和模型训练步骤的一致性，避免数据泄露问题。每个模型都使用相同的训练集进行训练，然后在相同的测试集上进行评估，保证了对比的公平性。

## 二、评估模型

模型评估阶段包括评估指标的选择、各模型性能的详细对比分析、ROC曲线的解读，以及最终模型的选择与保存。

我们选择了五个常用的分类评估指标：
- **Accuracy（准确率）**：整体分类正确的比例
- **Recall（召回率）**：在所有实际达标样本中，模型正确识别出的比例
- **Precision（精确率）**：在所有预测为达标的样本中，实际达标的比例
- **F1 Score**：精确率和召回率的调和平均数，综合衡量模型性能
- **AUC（ROC曲线下面积）**：衡量模型区分正负样本的能力，不受阈值影响

这些指标从不同角度反映了模型的性能。在实际应用中，我们更关注AUC和F1 Score，因为它们能够更好地反映模型在类别不平衡情况下的表现。

### 2.2 模型性能对比

![表12-16 模型各指标结果](../前端/analysis_results/classification_metrics_table.png)

*表12-16 模型各指标结果（加粗数值为每个指标的最优模型结果）*

从表12-16的模型评估结果来看，不同模型的表现存在显著差异：

**表现最佳的模型**：
- **MLP Classifier**在所有指标上都表现突出，AUC达到0.956，准确率为0.89，F1 Score为0.92。这个结果有些出乎意料，因为通常梯度提升树模型（如XGBoost）在这种结构化数据上表现更好。可能的原因是多层感知器能够捕捉特征之间的复杂交互关系，而我们的特征工程（包括独热编码）产生了大量的特征，为神经网络提供了丰富的输入。

- **KNN Classifier**紧随其后，AUC为0.922，准确率为0.88。KNN的表现也相当不错，这可能说明数据中存在明显的局部模式，即相似的学校在达标率上往往相近。

**梯度提升模型**：
- **XGBoost Classifier**和**XGBoost**的AUC分别为0.908和0.906，表现稳定但略低于预期。这可能是因为数据中存在较多的分类特征，而XGBoost在处理高维稀疏特征（如独热编码后的特征）时不如处理原始特征那么高效。

- **LGBM Classifier**的AUC为0.899，表现与XGBoost相当。

**树模型**：
- **Random Forest Classifier**和**RandomForest**的AUC分别为0.891和0.867，表现中规中矩。值得注意的是，Random Forest Classifier的召回率达到了0.95，是所有模型中最高的，这意味着它能够识别出更多的达标样本，但代价是精确率相对较低（0.85）。

- **Decision Tree**的AUC为0.862，虽然准确率较高（0.85），但AUC相对较低，可能存在一定的过拟合风险。

**线性模型**：
- **Logistic Regression**、**LinearRegression**和**Lasso**的AUC都在0.867-0.869之间，表现相近。这说明线性模型能够捕捉到数据中的主要模式，但可能无法很好地处理非线性关系。

**表现较差的模型**：
- **SVM Classifier RBF**和**SVM Classifier Linear**的AUC分别为0.436和0.355，远低于随机分类器的0.5。这个结果非常异常，可能的原因包括：
  1. 训练过程中没有完全收敛（尽管我们设置了max_iter=1000）
  2. 特征维度过高，导致SVM无法有效学习
  3. 数据预处理可能不适合SVM（如标准化可能不够充分）

- **Naive Bayes**的AUC为0.731，虽然精确率很高（0.98），但召回率极低（0.30），这说明模型过于保守，只对非常确定的样本才预测为达标。这可能是因为特征之间并不满足独立性假设，导致模型性能下降。

从图12-14的ROC曲线可以看出，大部分模型的曲线都明显高于对角线（随机分类器），说明这些模型确实学到了有用的模式。MLP Classifier的曲线最接近左上角，说明它在不同阈值下都能保持良好的性能。KNN和XGBoost的曲线也相当接近，说明它们都是可靠的模型选择。

### 2.4 模型选择与保存

基于AUC指标，我们选择了**MLP Classifier**作为最佳模型，并将其保存为`best_classification_model.pkl`。这个模型在测试集上的AUC为0.956，准确率为0.89，F1 Score为0.92，能够很好地平衡精确率和召回率。

在实际应用中，如果更关注召回率（即希望尽可能多地识别出达标的学校），可以考虑使用Random Forest Classifier，它的召回率达到0.95；如果更关注精确率（即希望预测为达标的样本尽可能准确），可以考虑使用Naive Bayes，虽然它的整体性能较差，但精确率高达0.98。

## 三、总结与思考

通过这次建模实践，我学到了几个重要的经验：

1. **模型选择的重要性**：不同类型的模型在不同数据上的表现差异很大。线性模型虽然简单，但在某些情况下也能取得不错的效果；而复杂的模型（如SVM）如果配置不当，可能表现很差。

2. **特征工程的影响**：特征的选择和预处理对模型性能有重要影响。我们通过独热编码将分类特征转换为数值特征，虽然增加了特征维度，但为模型提供了更丰富的信息。

3. **评估指标的多样性**：单一指标可能无法全面反映模型性能。我们需要综合考虑多个指标，并根据实际应用场景选择合适的模型。

4. **计算资源的利用**：GPU加速确实能够显著提高训练速度，特别是在处理大规模数据时。但也要注意，并不是所有模型都能从GPU加速中受益。

5. **模型可解释性**：虽然MLP Classifier表现最好，但它的可解释性较差。在实际应用中，可能需要在性能和可解释性之间做出权衡。

总的来说，这次建模任务让我对分类问题有了更深入的理解，也让我意识到模型选择、特征工程和评估指标选择的重要性。虽然最终选择了MLP Classifier作为最佳模型，但其他模型（如KNN、XGBoost）的表现也相当不错，可以根据具体需求进行选择。
